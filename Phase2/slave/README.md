# `slave/` — Section 2 Slave Node

Quick-start for **this node only** — used identically for both Slave 1
and Slave 2, just pointed at a different DB file. For the full picture
see [`../README.md`](../README.md) and [`../Report.md`](../Report.md).

## What this node does

Same single-endpoint lookup as Section 1's `slave_node`, now cache-first:
each `GET /query?type=&id=` checks this node's own local Memcached
before touching its local SQLite DB, replies with JSON including
`source":"CACHE"|"DB"` and `response_time_ms`, and writes a fresh DB
result back into the cache (300s TTL) for next time.

## Setup

```bash
cd slave
./run.sh
# Enter local SQLite database path [../slave1.db]: ../slave1.db   (or ../slave2.db on the other VM)
```

`run.sh` installs `libsqlite3-dev`, `memcached`, and `libmemcached-dev`
if missing, starts/enables the local `memcached` service, fetches
Mongoose into `src/` if needed, writes `env` (`PORT`, `DB_PATH`),
compiles, and runs `./slave_node` in the foreground.

Start **both** slaves before starting the Master — see
`../master/README.md`.

## Files here

| File | Purpose |
|---|---|
| `src/main.cpp` | `slave_node` source — cache-first single-endpoint local DB lookup |
| `Makefile` | `make` / `make clean` — links `-lsqlite3 -lmemcached` |
| `run.sh` | Installs deps incl. Memcached, configures, compiles, runs |
| `env` | Generated by `run.sh` (`PORT`, `DB_PATH`) |

## Stopping it

`Ctrl+C` — caught by a `SIGINT` handler, shuts down cleanly. Memcached
itself keeps running as a systemd service afterward.
