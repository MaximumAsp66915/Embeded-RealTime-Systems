# `master/` — Section 2 Master Node

Quick-start for **this node only**. For the full picture (two-layer
cache design, read/write flow, speed test analysis) see
[`../README.md`](../README.md) and [`../Report.md`](../Report.md).

## What this node does

Same HTTP gateway as Section 1's `master_node`, now cache-first: every
`GET /query?type=&id=` checks its own local Memcached before touching
`master.db` or cascading to a slave, and replies with JSON —
`{"value":...,"source":"CACHE"|"DB",...}` — including how long the
lookup took. See `../Report.md` Section 2 for the exact read/write
sequence.

## Setup

```bash
cd master
./run.sh
```

`run.sh` will:
1. Install `libsqlite3-dev`, `memcached`, and `libmemcached-dev` if
   missing, and start/enable the `memcached` service.
2. Prompt for the Master's gateway port, DB path, and each slave's
   NGINX-routed communication port (see Section 1's NGINX setup — this
   section doesn't automate NGINX itself; configure it manually per
   `../../Phase1/Report.md` Section 6, or reuse an already-running
   Section 1 NGINX instance).
3. Write `env`, fetch Mongoose into `src/` if needed, compile, and run
   `./master_node` in the foreground.

Run this **after** both slaves and (if used) NGINX are already up.

## Files here

| File | Purpose |
|---|---|
| `src/main.cpp` | `master_node` source — cache-first gateway, local DB fallback, cascade to slaves |
| `Makefile` | `make` / `make clean` — links `-lsqlite3 -lmemcached` |
| `run.sh` | Installs deps incl. Memcached, configures, compiles, runs |
| `env` | Generated by `run.sh` (`PORT`, `DB_PATH`, `SLAVE1_PORT`, `SLAVE2_PORT`) |

## Stopping it

`Ctrl+C` — caught by a `SIGINT` handler, shuts down cleanly. Memcached
itself keeps running as a systemd service afterward
(`sudo systemctl stop memcached` to stop it too).
