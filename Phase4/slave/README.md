# `slave/` — Section 4 Slave Node

Quick-start for **this node only** — used identically for both Slave 1
and Slave 2, just pointed at a different DB file. For the full picture
(SNMP layer, OID structure, data-path diagrams) see
[`../README.md`](../README.md) and [`../Report.md`](../Report.md).

## What this node does

Runs `slave_node` — **unchanged from Section 3**: an MQTT client that
subscribes to `cluster/slave/request`, checks its own cache then its
own local SQLite DB, and publishes the result (a value/name/description
or `NOT_FOUND`) to `cluster/slave/response`, tagged with whatever
`correlation_id` the request carried. There is no SNMP code on this
node at all — the SNMP agent (`snmpd`) and the pass-protocol bridge
both live only on the Master (see `../master/README.md`); a slave has
no idea an SNMP request is the reason it's being asked for a sensor —
from its point of view every request looks identical to a Section 3
MQTT query.

## Setup

```bash
cd slave
./run.sh
# Enter local SQLite database path [../slave1.db]: ../slave1.db   (or ../slave2.db on the other VM)
# Enter Target MQTT Broker Endpoint [tcp://192.168.56.101:1883]: tcp://192.168.56.101:1883
```

`run.sh` installs `libsqlite3-dev`, `memcached`, `libmemcached-dev`, and
`libpaho-mqtt-dev` if missing, points its local Memcached at `0.0.0.0`
if it was still on loopback-only, starts/enables the local `memcached`
service, writes `env` (`DB_PATH`, `MQTT_BROKER`), compiles, and runs
`./slave_node` in the foreground.

Start this **after** the Master (its broker and `snmpd` both need to
already be up) — see `../master/README.md`. Any sensor stored in this
node's local DB becomes reachable through the Master's SNMP tree
automatically, as long as its `sensor_id` is included in the Master's
`SENSOR_IDS` list — no configuration is needed on this node itself.

## Files here

| File | Purpose |
|---|---|
| `src/main.cpp` | `slave_node` source — MQTT client, cache-first local DB lookup, publishes to `cluster/slave/response` |
| `Makefile` | `make` / `make clean` — links `-lsqlite3 -lmemcached -lpaho-mqtt3c -lpthread` |
| `run.sh` | Installs deps, configures Memcached, compiles, runs |
| `env` | Generated by `run.sh` (`DB_PATH`, `MQTT_BROKER`) |

## Stopping it

`Ctrl+C`/`SIGTERM` — caught, disconnects from MQTT cleanly. Memcached
itself keeps running as a systemd service afterward.
