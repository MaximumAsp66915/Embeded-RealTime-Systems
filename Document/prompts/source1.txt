PROJECT OVERVIEW AND OBJECTIVES
-------------------------------
The objective of this project is the complete design and implementation of an
embedded system that receives a live camera feed, detects human presence, and
reports it via Web, Email, and the MQTT protocol. Upon power-up, the board must
operate autonomously without manual intervention, and all defined functions must
be active.

  * Required Hardware: Orange Pi board or a Linux Virtual Machine on a PC if the
    board is unavailable.
  * Mandatory Programming Language: C language for all sections (except Image
    Processing and Swagger, as explained later). FAILURE TO USE C IN ANY SECTION
    RESULTS IN A 25% SCORE DEDUCTION FOR THAT SECTION.

--------------------------------------------------------------------------------
OVERALL SYSTEM ARCHITECTURE
---------------------------
The system consists of three main components:
  1. Orange Pi Board: Hosts the Web Server, reads system sensors (temperature &
     memory), acts as an MQTT Client, sends emails, and enforces security
     measures in C.
  2. Image Processing Module: Detects the number of individuals.
  3. Personal Computer (PC): Runs the MQTT Broker and observes received messages
     on the relevant topics.

--------------------------------------------------------------------------------
OVERALL SECURITY REQUIREMENTS FOR THE PROJECT
---------------------------------------------
The following security measures must be strictly implemented throughout the
project; non-compliance will result in grade deductions:
  1. SSH Login: Restricted to public/private key or password. root login MUST be
     disabled.
  2. MQTT Login: Unauthenticated access must be disabled; a dedicated user with a
     password must be created.
  3. Hardcoding: No passwords or API keys may be hardcoded into the device.

  [Note on Swagger]: Since Swagger UI natively uses FastAPI (Python), you are
  allowed to use a thin FastAPI layer strictly as a documentation tool and API
  gateway, provided all core business logic (reading temperature/memory, counting
  people, executing commands) is implemented in C.

PART 1: WEB SERVER, AUTOMATED SERVICE, AND SSL (25 POINTS)
================================================================================

A) WEB SERVER SETUP
-------------------
  * Write an HTTP Web Server hosting an HTML page that displays:
    - Your name and student ID in the page title.
    - Live camera stream (If the board lacks a camera, use a webcam or stream a
      sample video/image from the laptop to the board).
    - Real-time count of detected individuals.
    - Processor temperature, free memory, and CPU utilization percentage live
      (updating every 2 seconds).

B) ADDING SSL WITH SELF-SIGNED CERTIFICATE
-------------------------------------------
  * Generate a self-signed certificate using OpenSSL. The CN field of the
    certificate must be your student ID.
  * The page must be accessible ONLY via HTTPS, and standard HTTP requests must
    automatically redirect to HTTPS (301 redirect).

C) SYSTEMD SERVICE
------------------
  * Write systemd service files so that upon board boot, all programs (Web
    Server, Image Processing, MQTT Client) start automatically without manual
    intervention.
  * Services must automatically restart upon crashing.
  * Service dependency order (e.g., Image Processing starting after camera
    initialization) must be managed using "After" and "Requires" directives, and
    explained with rationale using a flow chart in the report.

PART 3: IMAGE PROCESSING, EMAIL, AND MQTT (25 POINTS)
================================================================================

A) HUMAN DETECTION (Python allowed, C/C++ preferred)
----------------------------------------------------
  * Use a lightweight model to count people in the frame.
  * Frame output: bounding boxes + real-time person counter.
  * Overlay text on each frame: Student ID, Live System Date & Time.
  * Display actual FPS measurement on the video frame.

B) EMAIL NOTIFICATIONS
----------------------
  * Upon detecting 1 or more humans, send an email containing: person count,
    timestamp, CPU temp, and the attached frame screenshot.
  * Email sending logic must be written in C.
  * Implement a debounce mechanism: Maximum 1 email every 30 seconds. Explain
    this mechanism in the report.

C) MQTT
-------
  * Launch MQTT Broker (Mosquitto) on the PC.
  * MQTT Client running on the board must be written in C.
  * Mandatory Topic Structure:
      - home/persons/<student_id>
      - home/telemetry/<student_id>
  * Messages: JSON format containing person count, temp, and timestamp.
  * QoS = 1 and configure LWT (Last Will and Testament) to notify the PC upon
    sudden board disconnection.
