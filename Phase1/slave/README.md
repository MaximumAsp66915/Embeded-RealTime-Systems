# `slave/` — Section 1 Slave Node

Quick-start for **this node only** — used identically for both Slave 1
and Slave 2, just pointed at a different DB file. For the full picture
see [`../README.md`](../README.md) and [`../Report.md`](../Report.md).

## What this node does

Runs `slave_node`: an HTTP endpoint (Mongoose) that answers
`GET /query?type=<sensor_type>&id=<sensor_id>` against its own local
SQLite DB (`slave1.db` or `slave2.db`) and replies `200`+value or
`404 NOT_FOUND`. It has no awareness of the Master, NGINX, or the other
slave — it just answers whatever connects to its port, which in
practice is only ever the Master VM's NGINX cascading a request.

## Setup

```bash
cd slave
./run.sh
# Enter Binding Port for this Slave [8080]: 8080
# Enter local SQLite database path [../slave1.db]: ../slave1.db   (or ../slave2.db on the other VM)
```

`run.sh` installs `libsqlite3-dev` if missing, fetches Mongoose into
`src/` if needed, writes `env` (`PORT`, `DB_PATH`), compiles, and runs
`./slave_node` in the foreground.

Start **both** slaves before starting the Master — see
`../master/README.md`. Its `8080` needs to be reachable from the
Master's IP over the network (for NGINX's `proxy_pass` to reach it); it
does not need to be reachable from anywhere else.

## Files here

| File | Purpose |
|---|---|
| `src/main.cpp` | `slave_node` source — single-endpoint local DB lookup |
| `Makefile` | `make` / `make clean` — links `-lsqlite3` |
| `run.sh` | Installs deps, configures, compiles, runs (see above) |
| `env` | Generated by `run.sh` (`PORT`, `DB_PATH`) |

## Stopping it

`Ctrl+C` — caught by a `SIGINT` handler, shuts down cleanly.
