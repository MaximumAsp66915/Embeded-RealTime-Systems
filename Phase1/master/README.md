# `master/` — Section 1 Master Node

Quick-start for **this node only**. For the full picture (network
diagram, NGINX advanced-challenge write-up, database structure, request
cascade, security review) see [`../README.md`](../README.md) and
[`../Report.md`](../Report.md) — this file just covers what to type on
the Master VM itself.

## What this node does

Runs `master_node`: an HTTP gateway (Mongoose) that answers
`GET /query?type=<sensor_type>&id=<sensor_id>` by checking its own
`master.db` first, then cascading to Slave 1 and Slave 2 through a local
NGINX reverse proxy if it doesn't have the answer. See
`../README.md`'s architecture diagram for the full picture.

## Setup

```bash
cd master
./run.sh
```

`run.sh` will, in order:
1. Install `libsqlite3-dev` if missing.
2. Prompt for the Master's own gateway port, its SQLite DB path, and
   each slave's real IP + port.
3. Install NGINX if missing, write/enable
   `/etc/nginx/sites-available/api_gateway` from your answers, and
   reload it.
4. Write `env` (`PORT`, `DB_PATH`, `SLAVE1_IP`, `SLAVE1_PORT`,
   `SLAVE2_IP`, `SLAVE2_PORT`), fetch Mongoose into `src/` if needed,
   compile, and run `./master_node` in the foreground.

**Before starting `master_node` for real**, open `env` and confirm
`SLAVE1_PORT=8002` and `SLAVE2_PORT=8003` (NGINX's fixed local routing
ports) — `run.sh` currently writes each slave's *own* port there
instead, which breaks the cascade. Full explanation and the one-line
script fix: `../Report.md`, Section 8.

Run this **after** both slaves are already up (`../slave/README.md`).

## Files here

| File | Purpose |
|---|---|
| `src/main.cpp` | `master_node` source — gateway handler, local DB check, NGINX-relayed cascade to each slave |
| `Makefile` | `make` / `make clean` — links `-lsqlite3` |
| `run.sh` | Installs deps + NGINX, configures, compiles, runs (see above) |
| `env` | Generated by `run.sh`; edit `SLAVE1_PORT`/`SLAVE2_PORT` per the warning above |

## Stopping it

`Ctrl+C` — caught by a `SIGINT` handler, shuts down cleanly.
